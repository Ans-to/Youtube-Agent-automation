# Stop coding blind — Remotion production guide

A 10-second, 1080×1920, 30 fps Remotion composition based on the root [Skill.md](../../Skill.md). The isometric environment, monitor, keyboard and desk remain React Three Fiber / Three.js voxel geometry. The character is a detailed, clean 2D film-noir detective illustration parsed from inline SVG and displayed on a camera-facing plane; there is no voxel character. An animated orthographic camera moves through the scene. Words land with spring overshoot, RGB-split impacts and pixel glitches, over faint CRT scanlines.

[View the vector-character render notes](../../docs/media/remotion/stop-coding-blind-vector.md). The video is a draft until it is watched and listened to.

## Run

Node.js 20+ and a WebGL-capable browser are recommended:

```bash
cd video_studio/remotion
npm ci
npm run typecheck
npm test
npm run studio
npm run render             # out/stop-coding-blind.mp4
```

Remotion may download a compatible Chrome headless shell on first use. `remotion.config.ts` selects ANGLE for WebGL; on a GPU-less machine, software rendering can be selected with `npm run render -- --gl=swangle`. The 3D scene needs WebGL and will take longer than the former 2D render.

The rendered picture is exactly 300 frames (10 seconds). If an MP4 with an exactly 10.000-second container is required, use a system FFmpeg to copy the rendered video and encode the original soundtrack with a 10-second playback duration:

```bash
ffmpeg -i out/stop-coding-blind.mp4 -i public/audio/stop-coding-blind-120bpm.wav \
  -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k \
  -af 'pan=stereo|c0=0.70710678*c0|c1=0.70710678*c0,atrim=duration=10' \
  -t 10 -movflags +faststart out/stop-coding-blind-exact.mp4
```

## Beat and audio

The original instrumental is generated by `npm run audio`, using no outside samples. It is 48 kHz PCM on a 120 BPM grid beginning at time zero. The actual visible word impacts and their RGB/pixel glitches start on successive beats:

| Word | Time | Frame (30 fps) |
|---|---:|---:|
| Stop | 0.5 s | 15 |
| coding | 1.0 s | 30 |
| blind. | 1.5 s | 45 |

Additional short glitch accents occur every two beats. The camera path is frame-derived; the SVG detective gently bobs and gestures on the beat, while the terminal keeps typing and editing lines of code. The clip has music only: it does not request or generate a voiceover, so the skill's conditional TTS rules do not apply to this clip.

`StopCodingBlind` accepts `audioSrc?: string | null`. Omit it for the bundled track, pass a Remotion `staticFile(...)` URL to substitute a track, or `null` for silence. Replacements must be **120 BPM with beat zero at 0 seconds**; tempo/lead-in detection is not automatic.

## Structure

- `src/storyboard.ts` — exact words and beat events.
- `src/camera.ts` — deterministic 3D camera path.
- `src/VectorAvatar.tsx` and `src/avatarMotion.ts` — inline SVG noir detective billboard and beat-synced motion.
- `src/VoxelWorkspace.tsx`, `src/Voxel.tsx` and `src/terminalMotion.ts` — 3D room, terminal and keyboard.
- `src/GlitchOverlay.tsx` — beat-timed pixel flashes and CRT scanlines.
- `src/StopCodingBlind.tsx` / `src/Root.tsx` — synchronized composition and registration.
- `public/audio` and `public/fonts` — bundled soundtrack and licensed Space Grotesk font.

## Nokia Evolution preview

`src/nokia/NokiaEvolution.tsx` registers a separate 30-second, 1080×1920, 30 fps Remotion composition. Render locally with `npm run render:nokia`; the output is `out/nokia-evolution.mp4`.

The **Render Nokia Evolution (Remotion)** GitHub Action runs on pushes to `main` or the Arena task branch when Remotion sources, the workflow, or `Skill.md` change; it can also be started manually. It typechecks, tests, renders, and verifies the 900-frame MP4. Each successful render updates a public, prerelease preview asset at [Nokia Evolution — latest preview MP4](https://github.com/Ans-to/Youtube-Agent-automation/releases/download/nokia-evolution-preview/nokia-evolution.mp4). The run also keeps its MP4 artifact and a separate technical review-evidence artifact for 30 days.

The render uses the repository-configured Kokoro `am_michael` narrator and a quiet procedural score bed. Scene-line audio boundaries are measured from the generated WAV; individual word boundaries are estimates within those measured clips (not forced-alignment results). The Action checks the final MP4's streams, duration, frame count, frame rate, loudness/clipping, long silence, black-frame intervals, and freezes. Technical QA does not substitute for listening to and watching the exact output; this remains a review draft until a person does so.

For a local narrated render, install the pinned voice runtime, prepare the cached model, generate audio/cue props, then render:

```bash
cd video_studio/remotion
python -m pip install numpy==2.4.6 onnxruntime==1.31.1 kokoro-onnx==0.6.1
python ../kokoro_voice.py --dir "$HOME/.cache/agent-hq/kokoro" --voice am_michael
AGENTHQ_KOKORO_DIR="$HOME/.cache/agent-hq/kokoro" PYTHONPATH=.. python scripts/prepare_nokia_voice.py
npm run render:nokia -- --gl=swangle --props=out/nokia-evolution-props.json
```

The generated narration WAV is intentionally ignored by Git and can be recreated from `src/nokia/voiceover.json`. The direct-download release URL is updated on each successful workflow run.

The root [Skill.md](../../Skill.md) is the single shared source for current video-production rules. Technical checks do not substitute for visual or audio review.
