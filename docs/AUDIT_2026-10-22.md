## 4. Voice path — verified fail-closed

Both production guards were executed, not just unit-tested:

```
python3 video_studio/production.py --language ur-en --render-template --render
→ "Urdu-English production render is blocked pending human voice approval for the
   current voice profile. ... set urdu_voice_human_approved=true and
   urdu_voice_approved_profile_sha256 to this exact SHA-256: 9198ede5…"

python3 video_studio/production.py --language en --render-template --render
→ "English narration requires Piper and PIPER_MODEL pointing to a verified
   English voice model; silent output is not an acceptable fallback."
```

No eSpeak substitution and no silent track was produced in either case.

**Blocker.** No English Piper voice model can be obtained in this sandbox. The
official model the CI uses (`en_US-lessac-medium`) is published on HuggingFace,
which is unreachable, and the `rhasspy/piper` GitHub release asset redirects to a
host that is also blocked. GitHub mirrors of the file are Git LFS pointers (133
bytes). Consequence: the integrated pipeline cannot produce an MP4 here, and the
fail-closed guard is what prevents a fake one from being produced instead. This is
the exact blocker the issue's acceptance rule asks to be reported.

## 6. QA and recovery

- Retries are bounded: `run_role_with_retry` retries once, only for retryable
  errors, then raises with `retry_count` recorded.
- Tool timeouts are explicit (`video_studio` 14400 s, `product_studio` 900 s,
  model 240 s).
- The motion gate measures the delivered artifact rather than the intent:
  mean frame delta ≥ 0.90 and ≤ 20 % near-static frames, evaluated on the 4K
  master.
- The content audit reports `INCOMPLETE` rather than `PASS` when rules cannot be
  verified. 13 rules were unverifiable on the last film; `TQ-LIPSYNC` needs a
  face detector that does not match a flat vector face.

## 7. Defects found and fixed in this pass

1. **`requirements-kani-tts.txt` was unsatisfiable.** It pinned
   `transformers==4.57.1` while `nemo_toolkit[tts]==2.4.0` declares
   `transformers<=4.52.0,>=4.51.0`. `pip install -r` failed with
   `ResolutionImpossible`, so the documented legacy Kani backend could never be
   installed. Resolved by moving NeMo and transformers together to 3.0.0 / 5.x.
2. **The same file shipped a vulnerable stack.** Once resolvable at NeMo 2.4.0,
   `pip-audit` reported ten advisories against transformers 4.51.3 alone. NeMo 3.0
   removes the transformers cap, which clears all ten.
3. **`npm audit` failed the build on registry outages.** A transport failure and a
   real finding both exited non-zero, so a flaky advisory service produced a red
   security step indistinguishable from a vulnerability. Replaced with
   `tools/audit_npm_dependencies.py`, which retries only transport failures,
   reports `AUDIT UNAVAILABLE` distinctly, and still fails immediately on any
   high/critical finding. 17 tests cover it.
4. **Python requirements were never audited in CI.** Added a step that runs
   `pip-audit` over the requirements the default setup installs.

## 8. Residual risk

- `requirements-kani-tts.txt` still resolves to advisories in `hydra-core` and
  `lightning` (and transitively `fsspec`). NeMo 3.0.0 caps them
  (`hydra-core<=1.3.2`, `lightning<=2.4.0`) below their fixed releases, so no
  requirements file can clear them while using NeMo. The backend is optional, is
  not installed by the Windows default (Piper), and is not imported by CI. The
  constraint is documented in the file.
- Dependabot alert APIs and code-scanning alerts are not readable with the token
  available to this session (`403 Resource not accessible by integration`), so the
  audit above is based on the dependency manifests, the Dependabot PRs, and
  `pip-audit`/`npm audit` rather than on the security dashboard.
- The Urdu-English voice profile still has no human listening approval. That cannot
  be produced by code.
